A person asked a question about a database. The question fits several
interpretations at once, and code has already found the one place where they
disagree and the exact choices on offer. Your only job is to word the question
that settles it, and to give each choice a short label a person can recognise.

The options below are fixed. You may not add one, drop one, merge two or change
which interpretations an option stands for. Every id printed below appears in
your answer exactly once, and no other id does.

Each option line is: id | the column path, or "table" and the table path when being a
row of that table is the whole meaning, with no value test, or "database" and a
database name, or "leave out the part" and a part of the question, or "through tables"
and the tables when only the joins differ | value, when the option
also pins a stored value | why it was picked | what the database says that column or
table holds, with a few values it stores | how many interpretations it keeps | the
tables and joins those interpretations go through, shown only when the options differ
in them.

How to word it:

- The question is one short sentence in plain words, about what the person meant. It
  never names a column, a table or an interpretation. No jargon, no SQL.
- Each label is at most 60 characters, and says what that choice means in the
  person's terms, not the column's name. Two labels are never the same.
- Each label says what makes that choice different from the other choices, in
  words a person who has never seen the database understands: name the thing the
  column holds, not the column.
- The question says what the choice changes about the answer they get.
- When the values shown are id numbers or codes, the label says so, like "the
  asset's id number": the answer will show those, not names.
- When the lines show tables and joins, choosing an option also changes how its rows
  connect to the rest of the question. Then the label says that connection in plain
  words, like "clubs in the coach's home city". It stays a label for that option,
  never a new choice about the connection.
- A database option: say what that database is about, from its tables, in plain
  words, like "the school records" or "the sports league data".
- A "leave out the part" option: say plainly which part of the question would be
  dropped, like "drop the year".
- A "through tables" option: say how the rows connect, from its tables and
  joins, like "the coach's own clubs" or "clubs in the coach's home city".
- A table option means only the rows of that table count. Say what those rows are in
  plain words, like "only the parcels on the refund list".
- Say nothing about which option is more popular. The counts are there so you can
  tell a broad choice from a narrow one, not to recommend one.
- When the options pin different stored values and the reasons say the person's
  own words are not stored, ask which of those values means their words, quoting
  them. Each label shows its stored value exactly as printed. Never guess what a
  code stands for: a wrong guess reads as a fact.

Output Format, JSON and nothing else:

{
  "question": "one short sentence",
  "options": [
    {"id": "the id exactly as printed below", "label": "at most 60 characters"}
  ]
}
