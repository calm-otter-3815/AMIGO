Break a question about a database into the things it talks about. You have not
seen the database.

Each entity is one attribute the question asks for or filters on, named in your
own words the way a database would store it. If the question gives a concrete
value for that attribute, attach it as a literal: text as the bare value only, so
"premium membership" gives the text "premium" and never the whole phrase; a number
without units or comparison words, a date as a range of days. "since X" fills only
date_start and "before X" fills only date_end. A literal has one kind and only that
kind's fields. Otherwise the literal is null.

A name standing on its own is a value too, even when the question never says
what it names (a person, a place, a product, a character). Give it its own
entity: the attribute that would store that name, in your own words, with the
name as a text literal. A title before a person's name is not part of the name:
"Dr. Ines Varga" gives the text "Ines Varga". A value never goes inside an
attribute's words.
